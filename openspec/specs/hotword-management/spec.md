## ADDED Requirements

### Requirement: 热词持久化管理
系统 SHALL 提供独立的热词管理能力，将聊天快捷问题、热词标记和预设答案保存到 MySQL 热词表中，并按租户隔离管理。

#### Scenario: 管理员新增热词
- **WHEN** 管理员在热词管理页面提交热词内容、热词标记、预设答案、分类、权重和启用状态
- **THEN** 系统 MUST 在当前租户下创建一条热词记录，并返回创建后的热词信息

#### Scenario: 管理员分页查询热词
- **WHEN** 管理员打开热词管理页面或点击刷新列表
- **THEN** 系统 MUST 按当前租户返回分页热词列表，且不得返回其他租户的热词

#### Scenario: 管理员编辑热词
- **WHEN** 管理员修改某条热词的标记、内容、预设答案、分类、权重、排序或启用状态
- **THEN** 系统 MUST 更新对应热词记录，并保持记录归属于当前租户

#### Scenario: 热词标记唯一性校验
- **WHEN** 管理员新增或编辑热词时提交的热词标记在当前租户下已被其他未删除热词使用
- **THEN** 系统 MUST 拒绝保存并提示热词标记已存在

#### Scenario: 管理员删除热词
- **WHEN** 管理员确认删除某条热词
- **THEN** 系统 MUST 将该热词从可管理列表和随机读取结果中移除

### Requirement: Redis 与 MySQL 双级热词缓存
系统 SHALL 使用 MySQL 作为热词权威数据源，并使用 Redis 缓存当前租户的启用热词池和热词预设答案。

#### Scenario: Redis 命中启用热词池
- **WHEN** 聊天页请求随机热词且 Redis 中存在当前租户的启用热词池
- **THEN** 系统 MUST 从 Redis 热词池中随机抽取最多 3 条热词返回

#### Scenario: Redis 缓存缺失时回源 MySQL
- **WHEN** 聊天页请求随机热词且 Redis 中不存在当前租户的启用热词池
- **THEN** 系统 MUST 查询 MySQL 中当前租户启用且未删除的热词，回填 Redis 后随机返回最多 3 条

#### Scenario: 热词变更后缓存失效
- **WHEN** 管理员新增、编辑、启停或删除热词成功
- **THEN** 系统 MUST 失效当前租户的 Redis 热词池缓存和对应预设答案缓存，确保后续读取可以回源 MySQL 获取最新数据

#### Scenario: Redis 命中预设答案
- **WHEN** 聊天流式问答请求携带热词标记且 Redis 中存在当前租户该热词标记对应的预设答案
- **THEN** 系统 MUST 直接返回 Redis 中的预设答案

#### Scenario: Redis 预设答案缺失时回源 MySQL
- **WHEN** 聊天流式问答请求携带热词标记且 Redis 中不存在对应预设答案
- **THEN** 系统 MUST 查询 MySQL 中当前租户启用且未删除的热词预设答案，并在命中后回填 Redis

### Requirement: 聊天页随机展示热词
系统 SHALL 在聊天页快捷问题区域展示后端随机返回的 3 条启用热词，并支持用户刷新。

#### Scenario: 首次进入聊天页加载热词
- **WHEN** 用户进入聊天页
- **THEN** 前端 MUST 调用随机热词接口并展示最多 3 条启用热词

#### Scenario: 用户刷新热词
- **WHEN** 用户点击快捷问题区域的刷新按钮
- **THEN** 前端 MUST 重新调用随机热词接口并更新展示的热词列表

#### Scenario: 用户点击热词
- **WHEN** 用户点击某条热词
- **THEN** 前端 MUST 将该热词内容填入聊天输入框，并保存该热词标记用于发送

#### Scenario: 用户编辑已选热词内容
- **WHEN** 用户点击热词后手动编辑聊天输入框内容
- **THEN** 前端 MUST 清空已保存的热词标记，避免误触发预设答案直答

#### Scenario: 没有可用热词
- **WHEN** 随机热词接口返回空列表
- **THEN** 前端 MUST 展示友好的空状态或隐藏热词按钮，且不得影响用户手动输入问题

### Requirement: 热词管理页面
系统 SHALL 提供前端“热词管理”页面，用于维护聊天快捷问题热词。

#### Scenario: 查看热词管理入口
- **WHEN** 用户登录系统并查看主导航
- **THEN** 前端 MUST 展示“热词管理”导航入口

#### Scenario: 新增或编辑热词表单校验
- **WHEN** 用户提交热词表单但热词内容或预设答案为空
- **THEN** 前端 MUST 阻止提交并提示用户补齐必要信息

#### Scenario: 启停热词
- **WHEN** 用户在热词管理页面点击启用或停用
- **THEN** 前端 MUST 调用后端状态接口，并刷新热词列表展示最新状态

#### Scenario: 删除热词二次确认
- **WHEN** 用户点击删除热词
- **THEN** 前端 MUST 要求用户确认后才调用删除接口

### Requirement: 热词预设答案直答
系统 SHALL 在聊天流式问答中识别热词标记，并在命中有效热词时直接返回预设答案。

#### Scenario: askStream 命中热词预设答案
- **WHEN** 聊天页向 `askStream` 提交问题且请求中包含当前租户启用、未删除热词的热词标记
- **THEN** 后端 MUST 跳过普通问答缓存、RAG 检索和大模型生成链路，直接通过 SSE 返回该热词的预设答案

#### Scenario: askStream 未携带热词标记
- **WHEN** 聊天页向 `askStream` 提交普通问题且请求中没有热词标记
- **THEN** 后端 MUST 保持原有普通问答缓存、RAG 检索和大模型生成流程

#### Scenario: askStream 热词标记无效
- **WHEN** 聊天页向 `askStream` 提交的热词标记不存在、已停用、已删除或不属于当前租户
- **THEN** 后端 MUST 不返回预设答案，并继续执行原有普通问答流程

#### Scenario: 热词直答响应结构
- **WHEN** 后端通过热词预设答案完成直答
- **THEN** SSE 响应 MUST 发送 `answer`、空 `citations` 和 `done` 事件，并持久化用户消息与助手消息
