## 新增需求

### 需求：检索指标评估任务
系统应通过定时异步任务，基于已持久化的检索日志评估 RAG 检索质量。

#### 场景：定时任务评估符合条件的日志
- **当** 检索指标任务针对配置的日期范围运行时
- **则** 系统应加载符合条件的 `retrieval_log` 记录并完成评估，且不阻塞在线 RAG 请求。

#### 场景：禁用任务时不评估日志
- **当** 检索指标任务被 YAML 配置禁用时
- **则** 系统应跳过定时评估，并保持在线 RAG 请求不受影响。

### 需求：可配置 TopN 候选召回
系统应为每个被评估 query 召回可配置数量的候选文档，默认值为 200。

#### 场景：使用默认候选数量
- **当** 未配置自定义候选数量时
- **则** 系统应为每个 `query_text` 召回 Top200 候选文档。

#### 场景：使用配置候选数量
- **当** YAML 配置了自定义候选 TopN 值时
- **则** 系统应在指标评估候选召回时使用该配置值。

### 需求：基于 LLM 估算召回率
系统应通过大模型识别原始命中文档集合外的相关候选文档，用于估算 Recall。

#### 场景：候选集中存在漏召回相关文档
- **当** LLM 判断某个 TopN 候选文档与 query 相关，且该文档不在原始命中文档集合中时
- **则** 系统应将其计为召回率估算中的 FN。

#### 场景：原始命中文档相关
- **当** LLM 判断某个原始命中文档与 query 相关时
- **则** 系统应将其计为 Recall 和 Precision 计算中的 TP。

### 需求：基于 LLM 估算精确率
系统应通过大模型判断每个原始命中文档是否与 query 相关，用于估算 Precision。

#### 场景：原始命中文档不相关
- **当** LLM 判断某个原始命中文档与 query 不相关时
- **则** 系统应将其计为 Precision 计算中的 FP。

#### 场景：计算精确率
- **当** 某条检索日志的 TP 和 FP 已完成计数时
- **则** 系统应按 `TP / (TP + FP)` 计算 Precision。

### 需求：召回率计算
系统应使用标准公式 `TP / (TP + FN)` 计算 Recall。

#### 场景：使用漏召回文档计算召回率
- **当** 某条检索日志的 TP 和 FN 已完成计数时
- **则** 系统应按 `TP / (TP + FN)` 计算 Recall。

#### 场景：召回率分母为 0
- **当** TP 加 FN 等于 0 时
- **则** 系统应将 Recall 存储为 0，并保留评估解释。

### 需求：评估结果持久化
系统应持久化检索指标评估结果，包括状态、计数、分数、模型元数据和解释。

#### 场景：评估成功
- **当** 某条检索日志评估成功时
- **则** 系统应持久化 TP、FN、FP、Recall、Precision、实际评估候选数量、LLM 解释和 SUCCESS 状态。

#### 场景：评估失败
- **当** 候选召回或 LLM 判断失败时
- **则** 系统应持久化 FAILED 状态和错误信息，且不停止整个批次。

### 需求：按日期筛选的指标统计 API
系统应提供按日期范围查询聚合指标和明细指标的 API。

#### 场景：用户查询日期范围统计
- **当** 用户选择开始日期和结束日期时
- **则** 系统应返回该范围内的平均 Recall、平均 Precision、评估样本数、失败数和趋势数据。

#### 场景：用户查询评估明细
- **当** 用户打开某日期范围的指标明细时
- **则** 系统应返回按 query 展示的指标结果、原始命中文档、漏召回相关文档和 LLM 解释。

### 需求：检索指标看板
系统应提供 RAG Recall 和 Precision 的统计页面。

#### 场景：看板展示指标
- **当** 用户打开 RAG 检索指标页面时
- **则** 系统应展示日期筛选、平均 Recall、平均 Precision、样本数、失败数、趋势图和评估明细行。

#### 场景：看板按日期筛选
- **当** 用户修改选中的日期范围时
- **则** 系统应刷新该日期范围下的指标卡片、趋势图和明细行。
