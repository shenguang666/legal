## 背景

当前系统在 RAG 检索链路中记录 query、命中文档和返回数量等信息，但这些运行日志不能直接反映真实召回质量。真实 Recall 需要知道是否存在未被原检索命中的相关文档，Precision 需要判断已命中文档是否与 query 相关。用户希望基于 `retrieval_log` 的 `query_text` 和命中文档集合，离线再次召回 TopN 候选文档，并由大模型评估相关性，最终在页面中按日期统计检索质量。

该能力横跨检索服务、LLM 调用、定时任务、数据库持久化和前端统计页面。评估过程可能调用大模型且 TopN 默认较大，因此必须通过定时异步任务执行，避免影响在线问答主流程。

## 目标与非目标

**目标：**
- 基于 `retrieval_log` 按日期范围抽取待评估 query 和原命中文档。
- 对每条 query 重新召回可配置 TopN 候选文档，默认 Top200。
- 使用大模型判断候选文档与 query 的相关性，识别原命中文档之外的相关文档，用于估算 FN 和 Recall。
- 使用大模型判断原命中文档是否相关，用于估算 TP、FP 和 Precision。
- 持久化评估明细、聚合指标、模型判断依据、状态和错误信息。
- 提供统计页面，支持按日期范围查看平均 Recall、平均 Precision、样本量、失败量、趋势和明细。
- 通过 YAML 配置控制任务开关、Cron、TopN、批次大小、并发、超时和模型参数。

**非目标：**
- 不在在线问答请求中同步执行大模型评估。
- 不把离线评估结果直接作为检索排序的实时反馈信号。
- 不替代人工标注数据集；大模型判断作为自动化近似评估结果，需要保留解释和置信信息。
- 不在本次变更中重构整个 RAG 检索架构。

## 设计决策

1. 使用定时异步任务驱动评估，而不是在检索日志写入时立即评估。
   - 理由：Top200 召回和大模型判断成本较高，异步批处理可控且不会阻塞主进程。
   - 替代方案：请求内实时评估；该方案会显著增加响应时间和失败风险。

2. 新增独立评估结果表，而不是把指标直接写回 `retrieval_log`。
   - 理由：一个日志样本可能被不同模型、不同 TopN 或不同规则重复评估，需要保存评估版本和状态。
   - 替代方案：扩展 `retrieval_log`；该方案不利于重跑、对比和失败恢复。

3. 将 TopN、批次大小、任务 Cron 和并发限制放入 YAML 配置。
   - 理由：不同环境的大模型成本和 ES 压力不同，需要运行时可配置。
   - 替代方案：硬编码默认值；该方案不便于运维调优。

4. 召回率使用大模型发现的原命中集合外相关文档估算 FN。
   - 理由：系统没有完整人工标注全集，通过 TopN 扩展候选集可近似发现漏召回。
   - 计算口径：TP 为原命中文档中被模型判定相关的数量；FN 为 TopN 候选中不在原命中集合且被模型判定相关的数量；Recall = TP / (TP + FN)。

5. 精确率使用大模型判断原命中文档相关性估算 FP。
   - 理由：Precision 关注已命中文档中有多少真实相关。
   - 计算口径：TP 为原命中文档中被模型判定相关的数量；FP 为原命中文档中被模型判定不相关的数量；Precision = TP / (TP + FP)。

6. 前端统计接口返回聚合和明细两类数据。
   - 理由：首页卡片和趋势图需要聚合指标，问题级排查需要明细、候选文档和模型解释。

## 风险与权衡

- 大模型判断不稳定：保存模型名称、提示词版本、原始判断结果和解释，支持后续重跑与抽样复核。
- Top200 仍可能漏掉相关文档：将 TopN 配置化，并在页面展示评估 TopN 和评估口径说明。
- 批量任务成本过高：配置批次大小、并发、每日最大样本数和任务开关。
- 检索日志表结构不确定：已确认使用 `retrieval_log`，命中文档字段为 `hit_chunk_ids`。
- 任务重复评估同一日志：以 retrieval log id、评估版本、TopN 和模型标识建立幂等约束。
- 评估失败导致统计偏差：明细记录 FAILED 状态，聚合结果区分成功样本数和失败样本数。

## 迁移计划

1. 确认 `retrieval_log` 表结构和命中文档字段格式。
2. 新增评估结果表和必要索引。
3. 新增 YAML 配置并默认关闭或低频运行。
4. 实现评估服务、LLM 判断服务和定时任务。
5. 新增统计 API 和前端页面。
6. 在测试环境运行小批量样本，确认成本、耗时和统计口径。
7. 生产环境开启定时任务，逐步扩大样本量。
8. 如需回滚，关闭 YAML 任务开关并保留历史评估结果表，不影响在线检索。
