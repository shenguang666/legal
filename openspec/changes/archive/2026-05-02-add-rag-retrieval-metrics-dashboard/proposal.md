## 背景与原因

当前 RAG 检索只在日志中记录 retrieved/returned 等运行信息，无法按日期统计真实召回率与精确率，也无法基于人工或模型标注发现漏召回文档。需要新增离线异步评估能力和统计页面，帮助运营与研发持续观察检索质量，避免评估逻辑阻塞用户问答主流程。

## 变更内容

- 新增 RAG 检索质量评估能力：基于 `retrieval_log` 中的 `query_text` 和命中文档，再次召回 TopN 候选文档，默认 Top200，支持 YAML 配置。
- 新增大模型评估流程：判断 TopN 候选中是否存在未出现在原命中文档集合中的相关文档，用于估算召回率；判断原命中文档是否与 query 相关，用于估算精确率。
- 新增定时异步任务：按日期范围批量评估检索日志，避免阻塞主进程和在线问答链路。
- 新增评估结果持久化：保存每条 query 的 TP/FN/FP、Recall、Precision、模型判断依据、评估状态和错误信息。
- 新增统计页面和接口：支持选择日期范围查看平均 Recall、平均 Precision、样本量、失败量、趋势和明细。
- 新增配置项：控制评估任务开关、Cron、TopN、批次大小、模型评估参数和并发限制。

## 能力范围

### 新增能力
- `rag-retrieval-metrics`：RAG 检索质量评估、定时异步统计、日期筛选查询和统计页面能力。

### 修改能力
- `user-knowledge-curation`：知识库检索链路需要暴露可复用的 TopN 召回能力，用于离线评估候选文档。

## 影响范围

- 后端：新增评估任务、服务、Mapper/Entity、REST API、YAML 配置和数据库表结构。
- 前端：新增 RAG 检索质量统计页面，支持日期范围筛选、趋势展示和明细查看。
- 数据库：使用现有 `retrieval_log` 表结构，并新增评估结果表。
- 大模型调用：新增离线评估提示词和调用链路，需控制批量任务成本、超时和失败重试。
- 运维：新增定时任务开关、批量大小、TopN 和并发配置，避免影响主业务请求。
