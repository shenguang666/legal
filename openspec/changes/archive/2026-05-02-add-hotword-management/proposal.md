## Why

当前聊天页的 `quickPrompts` 由前端硬编码，无法由运营或管理员按业务场景动态维护，也无法在不同租户下沉淀高频咨询问题。为了让快捷问题具备可配置、可缓存、可刷新和可管理能力，需要新增“热词管理”能力，将热词从静态代码迁移到后端持久化与缓存服务。

## What Changes

- 新增热词管理后端能力：提供热词新增、编辑、启停、删除、排序/权重、分页查询接口。
- 新增热词随机读取接口：聊天页每次读取 3 个启用热词，支持前端手动刷新重新随机获取。
- 新增 MySQL 热词表：持久化热词标记、热词内容、预设答案、分类、权重、启用状态、租户、创建/更新时间等信息。
- 新增 Redis + MySQL 双级读取策略：优先从 Redis 热词池读取，缓存缺失时回源 MySQL 并回填 Redis；热词变更后主动失效或刷新缓存。
- 新增热词预设答案直答能力：聊天页发送热词时携带热词标记，后端 `askStream` 命中后直接从 Redis 或 MySQL 获取预设答案返回，避免进入 RAG 与大模型生成链路。
- 新增前端“热词管理”页面：提供热词列表、创建、编辑、启停、删除、刷新等管理交互。
- 改造聊天页快捷问题区域：不再使用硬编码数组，改为调用后端随机热词接口，并提供刷新按钮；用户点击热词后发送时携带热词标记。

## Capabilities

### New Capabilities
- `hotword-management`: 管理聊天快捷问题热词，支持后台维护、Redis + MySQL 双级读取、随机获取 3 条热词以及前端刷新。

### Modified Capabilities

无。

## Impact

- 后端：新增热词实体、Mapper、Service、Controller、DTO/VO、Redis 缓存逻辑、热词预设答案直答逻辑和数据库 schema。
- 前端：新增热词管理页面与路由/导航入口，改造 `ChatView.vue` 的快捷问题读取与刷新交互。
- 数据库：新增热词管理表，字段与实体属性需要按项目规则添加中文注释。
- 缓存：新增 Redis key 命名与缓存失效策略，热词写入、启停、删除后需要更新热词池和预设答案缓存一致性。
- 权限/租户：接口需要沿用当前登录上下文中的租户与用户信息，避免跨租户读取或管理热词。
