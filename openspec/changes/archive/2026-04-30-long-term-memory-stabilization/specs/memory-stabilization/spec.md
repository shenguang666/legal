## 新增需求

### 需求：长期记忆必须基于摘要而不是单轮对话进行提取
系统必须只在会话摘要刷新之后执行长期记忆提取，并且必须以摘要文本作为身份、职业、情绪及其他稳定用户状态识别的主要输入。

#### 场景：基于摘要驱动提取
- **当** 某个会话达到配置的摘要刷新轮次
- **则** 系统必须先刷新会话摘要，然后才从摘要文本中执行长期记忆提取

#### 场景：未触发摘要时不得逐轮直接提取
- **当** 单轮对话结束但没有触发摘要刷新
- **则** 系统不得仅根据该单轮内容把身份、职业或情绪信息直接提升为稳定长期记忆

### 需求：长期记忆必须先进入候选态后再升级为稳定记忆
系统必须先把新提取出的长期记忆写入候选态，并且只有在后续摘要刷新周期中被重复确认后，才能升级为稳定记忆。

#### 场景：首次提取进入候选态
- **当** 系统第一次从摘要中提取到一条新的长期记忆
- **则** 该记忆必须先以候选记忆形式存储，而不是直接写成稳定记忆

#### 场景：重复命中后升级为稳定记忆
- **当** 相同的规范化记忆键和值在后续摘要刷新中再次被识别出来
- **则** 系统必须增加其确认次数，并在达到配置阈值后升级为稳定记忆

### 需求：长期记忆键必须做规范化并进行合并
系统必须把语义等价的记忆键统一到一个规范化键上，并且必须避免用不同别名存储重复语义的长期记忆。

#### 场景：别名归一化
- **当** 提取结果中出现 `job`、`职业`、`profession` 这样的等价键
- **则** 系统必须将它们统一规范为同一个记忆键 `profession`

#### 场景：冲突值处理
- **当** 某个规范化记忆键已经存在但新提取结果给出了不同的值
- **则** 系统必须应用冲突处理规则，除非新证据明显更强，否则不得覆盖旧值
