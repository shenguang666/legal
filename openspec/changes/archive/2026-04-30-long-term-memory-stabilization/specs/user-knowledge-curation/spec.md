## 新增需求

### 需求：用户外挂知识在分类前必须先经过过滤
系统必须先进行轻量级规则预过滤，再把对话内容送入基于 LLM 的用户外挂知识分类流程。

#### 场景：低价值内容被提前过滤
- **当** 某个对话语义块过短、仅包含寒暄、仅包含临时指令或明显属于低价值内容
- **则** 系统必须在进入 LLM 分类前直接丢弃它，并且不得把它写入用户知识候选库

### 需求：用户外挂知识必须被分类为 must、optional 或 forbidden
系统必须把每个候选对话语义块分类为 `must`、`optional` 或 `forbidden`，并且必须保存分类结果、分类理由以及提炼后的核心内容。

#### 场景：must 级知识立即写入
- **当** 某个候选内容被分类为 `must`
- **则** 系统必须持久化其核心内容，并立即写入用户外挂知识 Elasticsearch 索引

#### 场景：forbidden 级知识直接拒绝
- **当** 某个候选内容被分类为 `forbidden`
- **则** 系统不得把它存为有效用户知识，也不得把它写入 Elasticsearch

#### 场景：optional 级知识延迟复核
- **当** 某个候选内容被分类为 `optional`
- **则** 系统必须先把它存为待定知识，并把 Elasticsearch 写入延迟到后续基于摘要的复核阶段

### 需求：optional 用户外挂知识必须结合摘要再次复核
系统必须把待定的 optional 用户外挂知识与最新会话摘要一起复核，再决定是否激活或拒绝。

#### 场景：optional 复核后升级为有效知识
- **当** 某个待定 optional 内容在摘要复核时被判断为稳定的或可复用的高价值知识
- **则** 系统必须把它升级为有效知识，并写入用户外挂知识 Elasticsearch 索引

#### 场景：optional 复核后被拒绝
- **当** 某个待定 optional 内容在摘要复核时被判断为低价值或仅属于会话碎片
- **则** 系统必须把它标记为已拒绝，并保持其不进入 Elasticsearch

### 需求：用户外挂知识必须按核心内容去重
系统必须在写入有效用户外挂知识前，基于提炼后的核心内容执行去重检查。

#### 场景：重复核心内容不应重复写入
- **当** 新候选内容的核心内容与现有用户知识高度相同
- **则** 系统必须避免创建重复的有效记录，也必须避免重复写入 Elasticsearch 索引
