## 2. 清洗核心能力

- [x] 2.1 实现 `DocumentContentCleaner`，支持纯文本和 Markdown 两种输入，统一执行空白符规范化、控制字符清理、中文字符间空格合并和连续空行压缩。
- [x] 2.2 实现页码、版权声明、下载时间、打印时间、来源链接、官网导出说明、孤立 URL 等内置低价值行识别规则。
- [x] 2.3 实现重复页眉页脚识别，基于页面首尾位置、出现次数、页面比例、行长度和低价值模式联合判断，避免只按重复次数删除正文。
- [x] 2.4 实现 Markdown 安全清洗，保留标题、列表、编号条款、表格结构和有效正文，不破坏 `SemanticDocumentChunker` 的语义边界输入。
- [x] 2.5 实现法律短标题保护策略，确保“违约责任”“争议解决”“付款条款”等短标题不会仅因长度较短被删除。

## 3. 切块后质量过滤

- [x] 3.1 实现低质量切片过滤器，过滤纯页码、孤立链接、版权声明、下载时间、系统导出说明等明显无检索价值切片。
- [x] 3.2 将低质量切片过滤接入 `DocumentParseTaskService` 的 `persistChunks` 前置流程，确保过滤后的切片才写入 `kb_chunk`。
- [x] 3.3 确保包含合同条款、法律解释、业务字段或表格证据的有效切片不会被低质量规则误删。

- [x] 4.3 保持 NATIVE 和 MINERU_PRECISE 的现有选择、状态流转、失败重试和索引 outbox 行为不变。
