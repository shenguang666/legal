## 背景与原因

当前聊天消息已经记录 `chat_message.token_usage`，但缺少按自然日沉淀的 Token 消耗指标，管理员无法稳定查看每日成本趋势，也无法识别 Token 消耗最多的用户。需要参考 RAG 指标的日汇总批处理架构，新增可定时、可手动补跑、可配置 Top 用户数量的 Token 消耗统计能力。

## 变更内容

- 新增 Token 消耗日汇总能力：按租户和指标日期统计总 Token、消息数、用户数、平均每消息 Token、任务状态和统计时间。
- 新增 Token 消耗 Top 用户统计能力：每日按用户聚合 Token 消耗，保留配置数量内的 Top 用户明细，用于发现高消耗用户。
- 新增 YAML 配置：支持指标总开关、低峰 Cron、单轮处理日期偏移、批处理参数、Top 用户数量和失败重试等配置；每个 YAML 条目必须有中文注释。
- 新增定时任务与手动评估接口：默认按低峰窗口统计上一自然日，管理员可手动触发今天之前的历史日期或日期范围统计。
- 新增后台统计 API：支持按日期范围查询汇总卡片、日趋势、日汇总分页和某日 Top 用户明细。
- 新增前端 Token 指标页面：使用趋势图展示每日 Token 消耗和消息量，使用列表展示日汇总与 Top 用户。
- 新增幂等与重算机制：同一租户、指标日期、统计版本只保留一条日汇总；手动执行已完成日期时返回无需重复统计，必要时可刷新受影响统计结果。

## 能力范围

### 新增能力

- `token-usage-daily-metrics`：Token 消耗日汇总、Top 用户统计、定时/手动统计、日期范围聚合 API 和前端指标看板能力。

### 修改能力

- 无。

## 影响范围

- 后端：新增 Token 指标配置类、Entity、Mapper、Service、Worker、Controller、DTO 和状态枚举。
- 数据库：新增 Token 消耗日汇总表与 Top 用户明细表，所有表字段必须添加数据库注释，必要索引覆盖租户、日期、统计版本和用户维度。
- 配置：新增 `token.metric.usage` 配置前缀，包含开关、低峰 Cron、日期偏移、Top 用户数量、批处理和重试配置，所有 YAML 配置项必须有注释。
- 前端：新增或扩展指标看板入口，展示 Token 消耗趋势、日汇总分页、Top 用户排行和手动统计操作。
- 运维：定时任务会读取 `chat_message` 与会话归属关系聚合历史消息，需要关注大日期范围查询、索引、幂等、防重入和历史补偿策略。
